# ADR-0003: Ollama Minimal Design System with Tailwind CSS and `shadcn/ui`

## Status

Accepted — 2026-11-06

## Context

ระบบ PMS ที่รวมงานหน้าเคาน์เตอร์รายชั่วโมง/รายวัน งานสัญญารายเดือน/จดมิเตอร์ และหน้าเว็บบริการตนเองของผู้เช่า มีข้อมูลตัวเลขและสถานะจำนวนมาก หากใช้สีสันฉูดฉาด การ์ดซ้อนการ์ดหลายชั้น หรือรูปทรงปุ่มที่ไม่เป็นระบบเดียวกัน จะทำให้พนักงานตาล้าและเกิดความผิดพลาดในการกรอกตัวเลขได้ง่าย

## Decision

1. **ใช้ระบบการออกแบบ Ollama Minimal Design System ([design.md](../../design.md) / `DESIGN.md`):**
   - พื้นหลังขาวบริสุทธิ์ `#ffffff` (`canvas`) และพื้นรอง `#fafafa` (`surface-soft`)
   - สีหลักดำบริสุทธิ์ `#000000` (`primary`, กด `#090909`) และเส้นขอบบาง `#e5e5e5` / `#d4d4d4`
   - อนุญาตให้มีการ์ดพื้นดำเข้ม `#171717` (`surface-dark`) ได้ไม่เกิน **1 จุดต่อหน้า** เพื่อเน้นส่วนที่สำคัญที่สุด (เช่น กะแคชเชียร์ในฝั่ง `admin` หรือเวลานับถอยหลัง `Hold TTL` / สรุปยอดบิลในฝั่ง `client`)
2. **รูปทรง 2 ค่าเท่านั้น (Two-Radius Geometry):**
   - ทุกองค์ประกอบที่โต้ตอบได้ (ปุ่ม, ช่องกรอก, ตัวเลือก, แท็กคำสั่ง) ใช้ทรงแคปซูล `9999px` (`rounded-full`)
   - การ์ด ตาราง และกล่อง Terminal ใช้มุมโค้ง `12px` (`rounded-lg`) ขอบ `1px solid #e5e5e5` โดยห้ามซ้อนการ์ดมีขอบไว้ในการ์ดมีขอบอีกชั้น
3. **ระบบฟอนต์ 3 ระดับ:**
   - หัวข้อใหญ่ใช้ `SF Pro Rounded`, เนื้อหาและป้ายกำกับใช้ `ui-sans-serif`, และรหัสเอกสาร/เวลาถอยหลัง/เลขมิเตอร์/จำนวนเงินใช้ `ui-monospace` (`tabular-nums`)
4. **พัฒนาด้วย `Tailwind CSS` + `shadcn/ui`:**
   - ห่อหุ้มคอมโพเนนต์ทั้งหมดไว้ใน `frontend/src/components/ui/` ร่วมกับ `FormTabs` และ `useDeferredFileUpload`

## Consequences

- **ข้อดี:** หน้าจอทั้งฝั่ง `admin` และ `client` สะอาด คมชัด อ่านตัวเลขมิเตอร์และยอดเงินได้แม่นยำ ไม่มีปัญหา Contrast ต่ำหรือ Layout กระตุก
- **ข้อควรระวัง:** นักพัฒนาห้ามใช้สี Hex นอกระบบโทเค็น และต้องตรวจสอบด้วยเครื่องมือตรวจจับของ `impeccable` ไม่ให้มี Nested Cards หรือ Contrast ผิดเพี้ยนภายใน `.inverted-card`
